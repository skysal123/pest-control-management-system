  📝 Key Design Patterns

  1. Finds-or-creates customer — by phone number (same customer may enquire
  multiple times)
  2. PRG (Post-Redirect-Get) — POSTs redirect to GET to prevent form
  resubmission
  3. Role-based access control — _admin_required and _tech_required decorators
  4. Status state machines — Lead status and Booking status have defined
  transitions
  5. Warranty as computed property — warranty_end = completed_at + WARRANTY_DAYS
  (not stored, always fresh)
  6. Notification deduplication — warranty_reminders table prevents duplicate
  emails
  7. Jinja template inheritance — base.html → admin/_layout.html →
  admin/dashboard.html
  8. Context processor globals — business_name, warranty_days, etc. available in
  all templates

  How the overlay works (so you can document it)

  The CSS background-image shorthand accepts multiple layers stacked
  top-to-bottom:
  background-image:
    linear-gradient(rgba(7,92,62,0.65), rgba(7,92,62,0.75)),  /* overlay on top 
  */
    url('bed-bug-control.webp');                              /* image below */
  The gradient is the first layer so it renders on top of the image, dimming the
  photo enough for white text to stay readable. The text-shadow on the
  heading/subtitle adds a secondary darkening under the letters so the photo
  detail behind them doesn't compete visually.

  How to add images for other services later

  Two paths:

  A. Per-service (recommended) — drop the file into
  app/static/images/services/<slug>.webp (e.g. termite-control.webp) and the
  templates will auto-detect it via the slug → image convention. To be precise,
  the current check is if not svc_image and s.slug == 'bed-bug-control'. If you
  want a generic convention, change the two lines to:

  {% set svc_image = 'services/' ~ s.slug ~ '.webp' %}

  Then drop matching .webp files for every service and the hero/card will pick
  them up automatically. No DB or admin changes needed.

  B. Database-driven — the Service model already has an image column
  (models.py:82). To use it, set service.image = 'services/xxx.webp' (just the
  static path) and the existing {% set svc_image = service.image %} line at the
  top of service_detail.html and home.html will use it automatically. Best for
  admins who want to manage images without code changes.
